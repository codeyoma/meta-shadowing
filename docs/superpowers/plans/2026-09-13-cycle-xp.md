# Cycle XP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Credit each confirmed cycle once, preserve historical XP, and show the approved 999-level curve.

**Architecture:** Journal's SQLite transaction owns cycle credit, checkpoint, completion, streak and backup revision. A compact per-run frontier ledger makes retries and stale saves idempotent, and version-2 backup exports preserve it while importing version-1 data without retroactive credit. Presentation consumes the resulting language summary.

**Tech Stack:** Expo 57, React Native 0.86, TypeScript, expo-sqlite, node:sqlite integration tests.

**Spec:** docs/superpowers/specs/2026-09-13-cycle-xp-design.md

## Global Constraints

- Each explicitly confirmed sentence cycle earns 1 XP, including both optional extra cycles.
- No new 10-XP run bonus or daily XP cap. Historical 0/10 XP records remain unchanged.
- Maximum level is 999. Formula: `round(100 * 1.0053^(level - 1) / 10) * 10`; cumulative cap threshold is 3,669,390 XP. Total XP saturates at 2,147,483,647 without losing completion history.
- Language totals are separate. Stages 1–16 still require three full runs; streaks still require a full-run completion.
- Store a monotonic phrase/confirmation frontier and credited total per run, not a row per sentence.
- Version-2 backups accept version-1 data without retrospective credit; retain strict validation, 16 MiB/100,000-row limits, atomic restore, nonempty-profile and newer-backup guards.
- iOS 26+ only. No Supabase, new dependency, physical-device fixture injection, sound, new goal UI, remote write, commit, push, merge or cleanup of existing user changes.
- The existing native worktree and dirty baseline are intentional. Reviews use a before/after worktree snapshot, not unrelated branch changes. Keep uncommitted review evidence; do not delete it as if recorded in commits.

- [x] **Step 2: Implement compact atomic cycle credit, then extend red/green behavioral coverage.**

Use a single row per package/stage/run bound to language/book, holding phrase count, frontier phrase, confirmed count, credited total and optional completion-day linkage. Lazy baseline from the existing persisted checkpoint on first encounter must preserve all prior confirmations but credit zero; an unseen progressed checkpoint also baselines zero. An unseen fresh run at phrase zero/confirmed zero starts at zero. Existing completed runs never receive new credit. Record and compare the prior checkpoint before overwriting it in Journal's transaction.

Credit only a one-confirmation advance from a durably saved speaking state, including third-cycle Repeat and third/fifth-cycle Next. A decision-to-next transition earns zero. When Next advances the phrase and resets confirmed to zero, credit the preceding final cycle exactly once. Monotonic frontier prevents rewind/replay credit. Reject inconsistent run identities, skips or impossible same-run transitions safely. Preserve pause, audio-end, rate changes and ready/listening/speaking stage-entry replay without awards. Completion ledger/study-day updates remain atomic; do not call the former bonus-awarding path.

Expected values are literal 1, 3, 5, 6, 8 as appropriate, independently counted, never derived using production reward helpers. Add real legacy-table fixtures showing old 20 XP stays 20 and a new confirmation becomes 21, with no old checkpoint catch-up. Verify new runs and stages on the same day continue earning; language/book/version bindings do not mix. Existing snapshots without identity may persist learning without earning XP.

Run focused tests after each red/green change. Failure-injection assertions must cover XP, checkpoint, completion, streak and backup revision where applicable.

Test summary across the cap using a valid bounded ledger fixture and ensure subsequent completion persists.
